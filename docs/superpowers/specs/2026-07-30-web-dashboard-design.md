# Web Dashboard — минимальная статическая страница поверх существующего API

## Проблема

Единственный интерфейс сервиса сейчас — Telegram-бот. Пользователь хочет
дополнительный визуальный способ посмотреть те же данные (курс, рекомендацию,
банковские курсы, статус источников) в браузере, с графиком курса во времени
и аккуратно оформленной статистикой, не заводя отдельного тяжёлого фронтенда.

## Архитектура: статика + тонкие роуты внутри существующего `api`-контейнера

Три варианта обсуждались:

1. **Статика + новые роуты в существующем `api`-контейнере** — ноль новых
   процессов, ноль новых зависимостей (Starlette `StaticFiles` уже входит в
   FastAPI).
2. Отдельный контейнер под статику (nginx/caddy) — архитектурно чище
   (разделение веб-слоя и бизнес-логики), но лишний процесс на и так
   ограниченной по памяти production VM (см. `project_vm_memory_constraints`
   в истории проекта — VM уже уходила в исчерпание памяти при параллельной
   сборке образов).
3. Отдельный Python/FastAPI-процесс только под фронтенд — дублирует то, что
   уже есть в `api`, plus ещё один процесс в памяти.

**Выбран вариант 1.** Пользователь подтвердил, что вариант с отдельным
FastAPI-инстансом можно рассмотреть позже, отдельным этапом, не сейчас.

Бизнес-логика не меняется и не дублируется: новые роуты — тонкие обёртки над
уже существующими `RecommendationService`, `RateService`,
`CollectorHealthService` (тот же слой, который уже использует
`app/bot/main.py`). Это соответствует границе "API-слой не содержит
бизнес-логику" из `CLAUDE.md`.

## Компоненты

### Новые роуты (по образцу `app/api/routes/rates.py` — один файл на ресурс)

- `app/api/routes/advice.py` — `GET /advice`, оборачивает
  `RecommendationService.get_recommendation()`.
- `app/api/routes/banks.py` — `GET /banks`, оборачивает `RateService` для
  4 банковских источников + медианы (`BANK_AVERAGE_SOURCE_NAME`).
- `app/api/routes/status.py` — `GET /status`, оборачивает
  `CollectorHealthService.get_status()`.

### Новые схемы (по образцу `app/schemas/rates.py`)

- `app/schemas/advice.py` — `RecommendationFactorResponse`,
  `RecommendationResponse` (action/confidence/summary/factors) — структурные
  поля, а не готовый форматированный текст (в отличие от бота, где текст
  собирается под Telegram); фронтенд сам решает, как красиво отрисовать.
- `app/schemas/banks.py` — `BankRateResponse` (source, value | null),
  `BanksResponse` (список банков + медиана | null).
- `app/schemas/status.py` — `SourceStatusResponse` (source, base_currency,
  quote_currency, last_observed_at | null, is_stale).

Существующий `/rates/history` и `/rates/latest` переиспользуются как есть —
новых эндпоинтов под график не требуется.

### Статика

- `app/static/index.html` — одна страница, три вкладки (переключение чисто на
  клиенте, без повторных запросов): "Курс и рекомендация", "Банки", "Статус".
- Vanilla JS (без сборки, без npm) — `fetch()` к перечисленным выше роутам +
  `/rates/latest`/`/rates/history`.
- График — Chart.js через `<script>` с CDN, две линии: официальный курс ЦБ
  Армении (`CBA_SOURCE_NAME`) и банковская медиана
  (`BANK_AVERAGE_SOURCE_NAME`), обе через уже существующий `/rates/history`.
  CDN — единственная внешняя сетевая зависимость страницы; для публичного
  read-only дашборда личного пользования это принятый компромисс, не
  заведено как versioned/vendored ради простоты.

### Изменение `app/main.py`

Монтирование `StaticFiles(directory="app/static", html=True)` на путь
`/dashboard`, регистрация трёх новых роутеров. Текущий `GET /` (JSON
`{"name", "status", "docs"}`) не трогается — сознательно не конфликтует с
корнем, чтобы не менять поведение уже существующего эндпоинта.

## Data flow

1. `GET /dashboard/` отдаёт `index.html`.
2. При загрузке JS параллельно запрашивает: `/advice`, `/banks`, `/status`,
   `/rates/latest?source=CBA...`, `/rates/history?source=CBA...&since=...`,
   `/rates/history?source=Bank+Average...&since=...`.
3. Каждый запрос обрабатывается независимо (см. "Обработка ошибок" ниже) —
   вкладки заполняются по мере готовности данных.
4. Переключение вкладок — на клиенте, без сети.
5. Обновление данных — только через перезагрузку страницы (без авто-рефреша
   и без WebSocket/SSE — сознательное упрощение, страница не предполагает
   постоянно открытой вкладки).

## Обработка ошибок

- `/advice` — `404`, если `RecommendationService.get_recommendation()`
  вернул `None` (недостаточно данных) — та же семантика, что уже у
  `/rates/latest`, не вводим новое соглашение.
- `/banks` — терпит частичные `None` по отдельным банкам (как уже делает
  `format_banks_reply` в боте); `404` только если все банки одновременно
  `None` — то же условие, что уже в боте.
- `/status` — всегда `200`: "нет данных"/"устарело" уже часть самого
  ответа `CollectorHealthService`, не ошибка.
- Фронтенд: каждая вкладка грузится и обрабатывает ошибку независимо
  (`try/catch` на каждый `fetch`) — `404` на одной вкладке показывает
  "пока нет данных" только в ней, не блокируя остальные.

## Тестирование

- `tests/api/test_advice.py`, `tests/api/test_banks.py`,
  `tests/api/test_status.py` (новые, по образцу `tests/api/test_rates.py`) —
  dependency override на сервисный слой, проверка кода ответа и формы JSON,
  включая `404`-кейсы и частичные банковские данные.
- `ruff`/`mypy --strict` покрывают только новые `.py`-файлы (роуты, схемы).
  `index.html` и встроенный в него JS — вне Python-тулчейна, CI их не
  проверяет; это ожидаемое ограничение для данного этапа, не пробел.
- После реализации — обязательная ручная проверка в браузере (вкладки,
  график, состояния "нет данных" на каждой вкладке), как того требует
  правило проекта для UI-изменений.

## Что сознательно не делаем сейчас

- Авто-рефреш/WebSocket/SSE — только загрузка по запросу пользователя
  (перезагрузка страницы).
- Аутентификация/защита доступа — дашборд публичный и read-only, те же
  данные уже отдаёт `/rates/latest` без токена.
- Отдельный контейнер/процесс под фронтенд (варианты 2 и 3 выше) —
  явно отложено, не является частью этого этапа.
- Локализация/интернационализация страницы — только русский текст, как и
  весь остальной пользовательский интерфейс проекта (бот).
- Vendoring/pinning Chart.js — используется CDN как есть, без версии,
  зафиксированной в репозитории.
- Изменение существующих `/rates/*` эндпоинтов — переиспользуются без
  изменений.
