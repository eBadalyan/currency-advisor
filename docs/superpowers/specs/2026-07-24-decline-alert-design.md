# Decline Alert — proactive Telegram notification on RUB weakening

## Проблема

Сейчас Currency Advisor — чисто pull-модель: бот отвечает на команды
(`/rate`, `/banks`, `/advice`, `/status`), но никогда не пишет пользователю
первым. Пользователь хочет, чтобы бот сам присылал уведомление, когда курс
начинает падать ("рубль слабеет"), — чтобы успеть разменять валюту до того,
как курс упадёт ещё ниже.

## Семантика триггера: trend-following, не mean-reversion

`RuleBasedRecommendationStrategy` (используется в `/advice`) — это
mean-reversion модель: курс выше своей скользящей средней трактуется как
"сейчас выгоднее обычного" (`EXCHANGE_NOW`), а падающий тренд тянет в
сторону `WAIT` (ждать возврата к средней). Это разумное допущение для
ликвидных, свободно плавающих пар, где отклонения — обычно временный шум
ликвидности, устраняемый арбитражем.

Курс наличного RUB в Армении — не такой рынок. Это структурно тонкий,
потоковый рынок (см. ROADMAP.md, раздел про `BankAverageService`):
ограниченная физическая ликвидность наличного RUB после 2022 года, движение
определяется реальными потоками (переводы мигрантов, отток/приток капитала),
а не двусторонним арбитражем. В таких рынках нет быстрого механизма,
"затягивающего" цену обратно к средней — локальный дефицит наличных не
устраняется мгновенно. Тренд, вызванный реальным дисбалансом спроса/
предложения, продолжается, пока не изменится сам поток.

Отдельно: push-уведомление по своей природе — сигнал раннего
предупреждения. Уведомление вида "не переживайте, скоро отскочит" не имеет
смысла как экстренный алерт — если ожидается возврат к среднему, прерывать
пользователя незачем.

**Решение:** для push-алерта используется отдельный trend-following
детектор, не связанный с `RuleBasedRecommendationStrategy`. `/advice`
не меняется — его mean-reversion логика остаётся валидной для своего
собственного вопроса ("выгодно ли сейчас относительно недавней истории").

## Источник сигнала

Основной триггер — банковский курс наличной покупки RUB, а именно медиана
четырёх банков (`Bank Average (RUB cash, derived)` из `BankAverageService`),
а не официальный курс ЦБ Армении, который использует `/advice`. Причина:
это курс, который пользователь реально получает при обмене наличных.
Официальный курс ЦБ добавляется в текст уведомления как дополнительный
контекст (тот же паттерн, что уже использует `/banks` — показывать оба).

## Архитектура

Разделение по существующим слоям проекта:

```
app/models/notification_state.py          — новая модель, таблица notification_states
app/repositories/notification_state_repository.py  — единственная точка доступа к этой таблице
app/services/decline_alert_service.py      — чистая детект-логика, без Telegram
app/bot/main.py                            — планировщик + сборка сообщения + отправка
```

- `NotificationState` — SQLAlchemy-модель, хранит состояние серии падений
  между проверками. Персистентно (переживает рестарт бота), не in-memory.
- `NotificationStateRepository` — read/write состояния по `signal_name`.
  Отдельный от `ExchangeRateRepository`, так как это другая сущность
  (состояние алертинга, не курс), но то же правило: без внешних API.
- `DeclineAlertService` — читает последнюю точку `Bank Average` через
  `ExchangeRateRepository`, сравнивает с состоянием через
  `NotificationStateRepository`, обновляет серию, возвращает
  `DeclineAlert | None`. Ничего не знает о Telegram/aiogram.
- `app/bot/main.py` — получает свой `AsyncIOScheduler` (aiogram уже
  поддерживает такое соседство с `dp.start_polling`), который раз в
  `decline_alert_check_interval_minutes` вызывает `DeclineAlertService`;
  при непустом результате собирает текст (комбинируя `DeclineAlert` с
  официальным курсом через `RateService`, как уже делает `/rate`) и шлёт
  `bot.send_message(admin_chat_id, text)`.

Доставка в Telegram остаётся полностью в Bot-слое (как и в
ROADMAP-диаграмме — "API / Telegram Bot" — слой доставки пользователю);
API-процесс (и его `collection_scheduler`) эту фичу не трогает.

## Модель данных

```python
class NotificationState(Base):
    __tablename__ = "notification_states"

    id: Mapped[int] = mapped_column(primary_key=True)
    signal_name: Mapped[str] = mapped_column(String(50), unique=True)
    last_value: Mapped[Decimal] = mapped_column(Numeric(18, 8))
    streak_length: Mapped[int]
    last_alerted_value: Mapped[Decimal | None] = mapped_column(Numeric(18, 8), nullable=True)
    updated_at: Mapped[datetime] = mapped_column(DateTime(timezone=True))
```

`signal_name` — сейчас всегда `"bank_average_decline"`, но поле есть с
самого начала, чтобы не переделывать схему, если позже появится второй
независимый сигнал (например, по конкретному банку, а не медиане).

Требуется новая Alembic-миграция.

## Алгоритм детекции

Состояние на сигнал `"bank_average_decline"`: `last_value`, `streak_length`,
`last_alerted_value` (`None`, если алертов по текущей серии ещё не было).

На каждой проверке:

1. Взять последнюю точку `Bank Average` из `exchange_rates`. Если точки
   нет (банковский кворум ещё не набран — см. `BankAverageService`) —
   выходим без изменений, состояние не создаём.
2. Если сохранённого состояния для `signal_name` ещё нет (самый первый
   запуск) — создать его с `last_value = текущее значение`,
   `streak_length = 0`, `last_alerted_value = None`, сохранить и выйти
   (сравнивать первое значение не с чем).
3. Если значение равно `last_value` — повтор того же скрапа (банк не
   обновлял котировку) — ничего не меняем, выходим.
4. Если значение **меньше** `last_value` — `streak_length += 1`.
5. Если значение **больше** `last_value` — серия сломана:
   `streak_length = 0`, `last_alerted_value = None`.
6. Обновить `last_value` на текущее значение.
7. Если `streak_length >= N` (по умолчанию `N=2`,
   `decline_alert_streak_threshold`) **и**
   (`last_alerted_value is None` **или** текущее значение <
   `last_alerted_value`) — это `DeclineAlert`: выставляем
   `last_alerted_value = текущее_значение`.
8. Сохранить состояние.

Почему `last_alerted_value`, а не булев флаг "уже алертили": флаг
заглушил бы уведомления на всё оставшееся многодневное падение после
первого срабатывания — курс может продолжать проваливаться неделями
(тонкий рынок), и пользователь узнал бы о новом, куда более глубоком дне
только зайдя в бота вручную. Значение вместо флага позволяет алертить
повторно ровно тогда, когда сформировалась новая серия из N падений
**ниже уже объявленного дна** — не на каждый тик (не спам), но и не
молчание на весь спуск.

`DeclineAlert` (простая структура, без Telegram-специфики):
```python
@dataclass(frozen=True, slots=True)
class DeclineAlert:
    current_value: Decimal
    streak_length: int
    previous_alerted_value: Decimal | None
```

## Конфигурация

Новые поля в `app/core/config.py` (`Settings`):
```python
telegram_admin_chat_id: int = 0
decline_alert_streak_threshold: int = 2
decline_alert_check_interval_minutes: int = 30
```
`telegram_admin_chat_id` проверяется на старте бота так же, как сейчас
`telegram_bot_token` (`raise RuntimeError`, если пусто) — лучше упасть на
старте, чем молча не слать уведомления.

Получатель — только один chat_id из конфига, без таблицы подписчиков.
Многопользовательская подписка — сознательно отложена: добавится, когда
проект дойдёт до полноценного продукта с ML (см. ROADMAP.md), сейчас была
бы преждевременной абстракцией.

## Текст уведомления

Собирается в `app/bot/main.py`, комбинируя банковский триггер (основной
сигнал) с официальным курсом ЦБ (контекст):

```
⚠️ RUB слабеет
Банковский курс наличной покупки RUB упал {streak_length} раз подряд, сейчас {current_value}.
[Ещё ниже, чем в прошлый раз я предупреждал ({previous_alerted_value}).]  — только если previous_alerted_value не пусто
Официальный курс ЦБ Армении: {cba_value}.
Возможно, стоит разменять сейчас, пока не упал ещё ниже.
```

## Тестирование

- `tests/repositories/test_notification_state_repository.py` — round-trip
  `get`/`save` на тестовой БД, по образцу `test_exchange_rate.py`.
- `tests/services/test_decline_alert_service.py` — сценарии на тестовой БД
  (по образцу `test_bank_average_service.py`):
  - нет алерта при недостаточной серии (`streak_length < N`);
  - алерт при `N` падений подряд;
  - повтор того же значения (тот же скрап) не продлевает и не сбрасывает серию;
  - рост курса сбрасывает серию и разрешает новый алерт при новом падении;
  - повторный алерт только на значение ниже уже объявленного дна, не на
    плато на уже объявленном уровне.
- Bot-уровень (сборка текста уведомления, вызов планировщика) — тонкий
  слой, тестируется аналогично существующим `format_*_reply` функциям в
  `app/bot/main.py`.

## Что сознательно не делаем сейчас

- Многопользовательская подписка (`/subscribe`, таблица подписчиков) —
  следующий шаг, когда появится ML и продукт станет полноценным.
- Изменение `RuleBasedRecommendationStrategy`/`/advice` — их mean-reversion
  логика не трогается, это отдельный, уже проверенный (Этап 9) взгляд на
  другой вопрос.
- ML-предсказание направления — по договорённости с пользователем, сейчас
  rule-based детектор, ML — следующий этап поверх того же контракта.
